# Builtin output parsers

PCTX41 parsers interpret stored, normalized, masked records. They do not run commands, read files, change trust, acknowledge delivery, or produce check-gate evidence. The source entry point is `parsers::parse(identity, records, child_exit, termination, capture_complete)`. Each record supplies `stream` (`stdout` or `stderr`), integer `sequence`, and UTF-8 `text`.

The caller must select the identity through a trusted executable and explicitly registered argv/reporter binding. A filename, a JSON key, a success sentence or a claimed parser name is insufficient. Tool versions and reporter flags belong in that binding. Registered check profiles select the reporter identity; CLI output and retained-artifact rerendering call this same interpretation contract. Plain manual commands do not gain a registered parser merely from their argv.

| Identity | Accepted representation | Preserved facts and limits |
| --- | --- | --- |
| `pctx-check-report-v1` | Complete native `CheckReport` JSON on stdout, schema version 1 | Key, producer, counts, times, claimed result and observed exit agreement. Zero tests, all skipped, positive failures/errors, missing fields or incomplete capture cannot become a pass. |
| `eslint-json-v1` | JSON array from the documented `json` formatter | Per-file errors, warnings, fatal counts, rule ID, severity, message, start/end line/column, suppressed-message count. Count mismatches are partial. `json-with-metadata` and other wrappers are unsupported in this variant. Fix text and source bodies are omitted. |
| `jest-json-v1` / `vitest-json-v1` | Explicitly registered Jest-compatible formatted JSON: aggregate test/suite counts, success/start time, suite name/status/times/message, assertion full name/status/failure messages | Failure, skip, todo, suite errors, explicit retry/invocation/flaky fields, locations and failure text. Missing final result or mismatched counts is partial. Native JSON does not establish complete retry history: this variant preserves observed pass counts but keeps the overall clean-pass interpretation unverified. |
| `typescript-text-v1` | Noncolored `path(line,column): error TSnumber: message`, or a global `error TSnumber: message` | Exact file/code/severity/location and capture record reference. Unrecognized or continuation lines make parsing partial and remain in bounded excerpts. Successful exit with no recognized diagnostics is not proof typechecking ran. |
| `git-status-porcelain-v1-z` | Exact `--porcelain=v1 -z` data, including final NUL | Index/worktree status, untracked/conflict counts and rename destination/source. Spaces and newlines inside paths are not split. This format does not supply HEAD/ref authority. Missing NUL framing is partial. |
| `git-log-nul-v1` | Fixed selected-field format `%H%x00%P%x00%s%x00` | Commit/parent IDs and subjects. Ref names, changed files and omitted history remain outside this representation. Caller records the actual selection/limit and HEAD separately. |
| `git-diff-unified-v1` | Ordinary unified Git diff | File headers, old/new paths, rename/add/delete/binary markers and original hunk line ranges. Staged/unstaged and base/HEAD identity require caller binding. Hunk bodies are not validated; parsing remains partial. This review view is never an applicable patch. |

Formats were checked against the official documentation on 2026-10-08: [Git status](https://git-scm.com/docs/git-status), [Git log](https://git-scm.com/docs/git-log), [Git diff](https://git-scm.com/docs/git-diff), [ESLint formatters](https://eslint.org/docs/latest/use/formatters/), [Vitest reporters](https://vitest.dev/guide/reporters), [Jest configuration](https://jestjs.io/docs/configuration#testresultsprocessor-string), and [TypeScript noncolored output](https://www.typescriptlang.org/tsconfig/pretty.html). Parser identity `v1` identifies PCTX's bounded representation contract, not a claim of support for every upstream release. Fixtures model these documented shapes; no installed upstream runtime or complete version matrix is asserted by writing them.

The returned versioned object includes `parse_status` (`complete`, `partial`, `unsupported`), explicit reasons, observed summary, bounded file items and diagnostics, omission counts, capture references, reported interpretation, child status and fallback excerpts. `gate_evidence` is always false. A structurally complete native report may preserve its consistent `passed` claim only after normal exit zero and complete capture; the runner must independently validate provenance, source/environment fingerprints, registration and task rules. Renderer output cannot substitute for that validation.

The parser examines at most 1 MiB of record text and 8,192 records, below the 16 MiB execution-capture ceiling. JSON additionally rejects duplicate keys, depth above 64 and more than 8,192 lexical nodes before deserialization. Oversized inputs return partial without attempting to decode them. Each collection retains at most 128 entries; omitted entry counts stay visible. Individual presentation strings retain at most 2 KiB, with explicit omitted-text markers; strings above 8 KiB are omitted before redaction to bound parser workspace. Failed parsing retains a small head/tail excerpt. Raw record identity remains the original-output retrieval route; omitted body text is not reconstructed.

Parser loops check a one-second cooperative deadline. Bounded JSON decoding, regex construction and masking are not interruptible timers. The pure API accepts caller-owned `Value` records, so its limits do not establish a hard 32 MiB process RSS guarantee; supervised memory/time enforcement and actual platform measurements remain integration requirements. Parent renderers must still enforce the complete final envelope's 8 KiB default budget and preserve exit/capture/count/reference fields first.

Masking is reapplied to emitted strings. Active path/topic/role policy, source freshness, original normalized-to-raw byte mappings, capture truncation, retention and policy-safe reread belong to the artifact service. File items remain distinct; matching messages across different files are never merged. Grouping/deduplication and full-range mappings require a later representation contract. Protected diagnostic omission is visible through collection counts and retrieval references, never silently turned into clean success.

Git NUL variants use NUL-preserving stdout capture only for an explicitly registered Git NUL identity. Embedded filename newlines and control characters survive as JSON-escaped data. Stderr keeps ordinary line framing. Missing separators, invalid UTF-8 and incomplete capture remain partial; ordinary binary command output does not opt into this framing. No parser changes argv, installs a reporter, enables a Git helper, uses the network or reruns an execution.

`tests/parsers.rs` contains independent shape and failure fixtures for native reports, ESLint ranges/count drift, test retries/crashes/final-result absence, TypeScript locations, Git machine filenames/ranges and input limits. Integration verification results belong in the implementation evidence log; fixture authorship alone is not a passing result.

Parser collections may be shortened further for the requested presentation budget. `presentation_omissions` counts those removed entries separately from parser/capture omissions. The summary, capture/exit status and reread reference remain explicit. Complete CLI envelope budgets also apply to nested registered check results; bytes successfully delivered are recorded against the original output artifact.
