# Independent core review

Reviewed on 2026-10-08 against specification §§6–14, §17 and AC01–22. Scope: domain, project, reader, storage, context, main, with search read paths inspected where the central reader returns data. This is an independent static review; reproduction recipes below have **not** been executed. No build or source changes were made by the reviewer during this review. Findings describe the reviewed source and must be rechecked after integration fixes.

## Blocking findings

| ID | Priority | Finding and evidence | Reproduction / acceptance test | Status |
| --- | --- | --- | --- | --- |
| CR01 | P1 | `storage::handoff_create` passes `.pctx/handoffs` to `private_dir` and `atomic_write` without checking intermediate symlinks. `private_dir` follows a pre-existing directory symlink, and `atomic_write` checks only the final target. A project can redirect this write outside its root and change external directory permissions. Violates §17 path boundary and AC10. | In an isolated fixture, link `.pctx/handoffs` to another temporary directory, then call `handoff create --from-file INPUT --name sample`. Require `POLICY_DENIED` and no external file or permission changes. | Open; reported to integrator |
| CR02 | P1 | `search::read_selection` slices and truncates the source before calling `reader::redact`; find snippet masking similarly receives only a fragment. The multiline private-key pattern needs both delimiters. A key embedded in an allowed `.txt` or source file leaks when a request selects its middle or truncates before the closing delimiter. Context full-source masking avoids this particular issue. Violates §17 credential-output invariant. | Synthetic allowed text contains a BEGIN PRIVATE KEY line, 90 lines of synthetic base64-like content, and END PRIVATE KEY. Default `read` and `read --lines 2:3` must not return secret-block contents; find a middle-line marker with a narrow snippet must also mask it. Use synthetic data only. | Open; reported to integrator |
| CR03 | P1 | `context::build` gets indexed entries, reads the current candidate, then attaches `entry.symbols` for outline/signature without checking `entry.file_hash == current.hash`. Its final source recheck compares the newly read hash, so it does not detect an edit made between indexing and candidate reading. This pairs stale ranges and symbols with a new file hash. Violates AC05 and §12 selected-version validation. | A deterministic test hook edits a seeded file between `storage::snapshot` and candidate read. Outline/signature build must reparse the new version or fail `CONCURRENT_MODIFICATION`/`STALE_INDEX`; it must never label old symbol spans with the new file hash. | Open; reported to integrator |
| CR04 | P1 | `context::build` discards the coverage result of `storage::update` and `inventory.skipped`. `--require-complete` only rejects budget omissions. Missing analysis or walking failures can therefore produce a normal context and `selection_complete=true`. Violates §12 require-complete and explicit partial failures. | Fixture contains a UTF-8 file exceeding `max_file_bytes` or an inaccessible allowed directory, with another readable seed. `build --task fixture --require-complete` must fail with structured partial reasons. Ordinary build must expose the incomplete input universe. | Open; reported to integrator |
| CR05 | P1 | Main marks partial output only when `data.coverage` equals the string `partial`. Find returns a coverage object, outline returns nested per-file coverage, and read returns `completeness`/`truncated`. Thus parser failure, scan exhaustion, and omitted read bodies leave the public envelope `coverage=complete`, `truncation=false`, and sometimes exit 0. Default matched candidate-space uncertainty may remain exit 0 with warning, but actual incomplete execution must propagate. Violates §§8/14 and AC18. | Outline syntactically invalid Python; read more than 80 lines; force find's scan limit. Verify public envelope contains corresponding partial/unsupported and truncation metadata and required failure exit behavior. | Open; reported to integrator |

## Completeness gaps, separate from defects

These are implementation scope still needing tracking; they are not claims that an existing safety check failed.

- Configuration precedence, user security-deny union, hidden-file default handling, strict typed validation of search/context/role settings, and use of configured defaults are incomplete (§7).
- `index rebuild` routes to ordinary update; staging/replacement recovery for corrupt or unusable index files is absent (§§9–10).
- Context task-ID integration, structured required-rule scope/conflict handling, ranking/test/document signals, and stable full-span/signature representation contracts remain incomplete (§12). Current source explicitly labels some coverage limitations.
- Checkpoints lack parser/config fingerprints and optional Git provenance. Scope selection, rename hints, and missing-local-checkpoint handoff fallback are incomplete (§13).
- Read supports a body cap, but does not enforce the serialized JSON envelope's 64-KiB limit or expose `--require-complete` for reads (§11).
- Doctor does not yet check directory permissions, projection/event integrity, orphan staged records, or Windows ACLs (§§9/17).
- No actual three-platform execution evidence was reviewed; AC22 remains unverified. No performance or resource limit evidence was reviewed.

## Positive observations

Index and control storage paths are physically separated. Index publication is transactional and snapshot selection uses only ready generations. Source bodies are not persisted in index metadata. Current policy is re-applied to indexed-file reads. Symbol reads compare exact source hashes. The Unix reader now walks with directory descriptors and `openat(O_NOFOLLOW)`; the reviewer did not identify an immediate Unix symlink read escape in that updated implementation. Core paths do not invoke a shell or network connector from repository configuration. These are static observations, not runtime acceptance results.
